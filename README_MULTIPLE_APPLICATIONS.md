# 多次申請功能說明

## 功能概述

現在程式支援根據 Excel 文件中 Config 工作表的列數進行多次申請。每一列代表一次申請，通常用於不同的入園日期。

## 使用方法

### 1. 準備 Excel 資料

在 `hike_application_data.xlsx` 的 Config 工作表中：
- 第一列：標題列（TeamName, MainRoute, SubRoute, TotalDays, EntryDate, 申請狀態 等）
- 第二列：第一次申請的資料
- 第三列：第二次申請的資料
- 以此類推...

**🆕 申請狀態功能**：
- 新增「申請狀態」欄位，用於追蹤申請進度
- 預設值：空白（未申請）
- 申請成功後：自動更新為 `applied`
- 已申請的列會被自動跳過，避免重複申請

其他工作表（Applicant, Leader, Members, StayBehind）的資料會在所有申請中重複使用。

### 2. 正式執行

```bash
node hike_apply.js
```

### 3. DRY RUN 模式（測試模式）

```bash
DRY_RUN=true node hike_apply.js
```

在 DRY RUN 模式下：
- 程式會正常填寫所有資料
- 到達驗證碼頁面時會顯示測試模式提示
- 您只需輸入任意值作為驗證碼
- 程式會假設申請成功，繼續下一次申請
- **不會真正送出申請**

## 執行流程

1. **資料過濾**：
   - 跳過申請狀態為 `applied` 的列
   - 跳過空白列
   - 跳過缺少入園日期的列
2. **批次申請**：對過濾後的資料進行申請
3. **申請流程**：
   - 正式模式：真正輸入驗證碼送出，成功後更新狀態為 `applied`
   - DRY RUN 模式：輸入任意值假設成功，不更新實際狀態
4. **狀態更新**：申請成功後自動在 Excel 中標記為 `applied`
5. **重複執行**：下次執行時會跳過已申請的項目

## 注意事項

- **申請狀態管理**：
  - 成功申請後會自動標記為 `applied`，避免重複申請
  - 支援多種欄位名稱：`申請狀態`、`ApplicationStatus`、`Status`、`狀態`
- **DRY RUN 模式**：適合測試程式功能，不會產生實際申請或更新狀態
- **正式模式**：會真正送出申請並更新 Excel 狀態，請確認資料正確
- **資料過濾**：自動跳過已申請、空白、或缺少必要欄位的列
- **斷點續傳**：程式中斷後可重新執行，會從未申請的項目繼續
